<p>It's fair to say that <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button> is a lot more intimidating to approach than Operating System's (OSs) such as Windows. <ul>
<li>Websites that you visit</li>
<li>Car entertainment/control panels</li>
<li>Point of Sale (PoS) systems such as checkout tills and registers in shops</li>
<li>Critical infrastructures such as traffic light controllers or industrial sensors</li>
<li>Phones, and similar small computing devices</li>
<li>And much much more!</li>
</ul>
<h2>&nbsp;</h2>
<h2>Flavours of <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button></h2>
<p>The name "<button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button>" is actually an umbrella term for multiple <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">OS</button>'s that are based on UNIX (another operating system). Thanks to <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button> being open-source, variants of <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button> come in all shapes and sizes - suited best for what the system is being used for.</p>
<p>&nbsp;</p>
<p>For example, Ubuntu &amp; Debian are some of the more commonplace distributions of <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">Linux</button> because it is so extensible. I.e. you can run Ubuntu as a server (such as websites &amp; web applications) or as a fully-fledged desktop. For this series, we're going to be using Ubuntu.</p>
<p><em>Note: Ubuntu Server can run on systems with only 512MB of <button type="button" data-testid="glossary-term" class="glossary-term" aria-haspopup="dialog">RAM</button>!</em></p>

<h2><strong>Searching Recursively with grep</strong></h2>
<p>Sometimes, the information we are looking for is spread across <strong>multiple files</strong> inside a directory. Instead of checking each file individually, we can tell <code>grep</code> to search <strong>recursively</strong> through all files and subdirectories.</p>
<p>To do this, we use the <code>-R</code> (recursive) option.</p>
<p>For example, to search for a variable across <strong>all files</strong> in the current directory and its subfolders, we can run:</p>
<pre class="language-bash" tabindex="0"><code class="language-bash"><span class="token function">grep</span> <span class="token parameter variable">-R</span> <span class="token string">"PRETTY_NAME"</span> /etc/</code></pre>
<p>This will:</p>
<ul>
<li>Search every file in the current directory</li>
<li>Search all subdirectories</li>
<li>Show where the PRETTY_NAME appears</li>
</ul>
<p>Example output:</p>
<pre class="language-bash" tabindex="0"><code class="language-bash"><span class="token function">grep</span> <span class="token parameter variable">-R</span> <span class="token string">"PRETTY_NAME"</span> /etc/
grep: /etc/sudoers: Permission denied
/etc/os-release:PRETTY_NAME<span class="token operator">=</span><span class="token string">"Ubuntu"</span></code></pre>

There are a few important operators that are worth noting. We'll cover the basics and break them down accordingly to bite-sized chunks.</p>
<p>At an overview, I'm going to be showcasing the following operators:</p><div class="table-scroll-wrapper"><table class="table table-bordered"><tbody><tr><td>Symbol / Operator</td><td>Description</td></tr><tr><td>&amp;</td><td>This operator allows you to run commands in the background of your terminal.</td></tr><tr><td>&amp;&amp;</td><td>This operator allows you to combine multiple commands together in one line of your terminal.</td></tr><tr><td>&gt;</td><td>This operator is a redirector - meaning that we can take the output from a command (such as using cat to output a file) and direct it elsewhere.</td></tr><tr><td>&gt;&gt;</td><td><p>This operator does the same function of the <code>&gt;</code> operator but appends the output rather than replacing (meaning nothing is overwritten).</p></td></tr></tbody></table></div><p>Let's cover these in a bit more detail.<br><br></p>
<h2>Operator "&amp;"</h2>
<p>This operator allows us to execute commands in the background. For example,  let's say we want to copy a large file. This will obviously take quite a long time and will leave us unable to do anything else until the file successfully copies.</p>
<p>The "&amp;" shell operator allows us to execute a command and have it run in the background (such as this file copy) allowing us to do other things!</p><p><br></p>
<h2>Operator "&amp;&amp;"</h2>
<p>This shell operator is a bit misleading in the sense of how familiar is to its partner "&amp;". Unlike the "&amp;" operator, we can use "&amp;&amp;" to make a list of commands to run for example <code>command1 &amp;&amp; command2</code>. However, it's worth noting that <code>command2</code> will only run if <code>command1</code> was successful.</p><p><br></p>
<h2>Operator "&gt;"</h2>
<p>This operator is what's known as an output redirector. What this essentially means is that we take the output from a command we run and send that output to somewhere else.</p>
<p>A great example of this is redirecting the output of the <code>echo</code> command that we learned in Task 4. Of course, running something such as <code>echo howdy</code> will return "howdy" back to our terminal — that isn't super useful. What we can do instead, is redirect "howdy" to something such as a new file!</p>
<p>Let's say we wanted to create a file named "welcome" with the message "hey". We can run <code>echo hey &gt; welcome</code> where we want the file created with the contents "hey" like so:</p>
